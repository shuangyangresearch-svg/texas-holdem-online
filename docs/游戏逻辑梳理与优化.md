## 一、系统架构

```
┌─────────────────────────────────────────────────────────┐
│ 客户端 (public/) 原生 JS + Socket.IO(polling)            │
└──────────────────────────┬──────────────────────────────┘
                           │ room:state / room:state:me / game:action ...
┌──────────────────────────▼──────────────────────────────┐
│ server.js — Express + Socket.IO 服务层                    │
│   · 鉴权(register/login/session token)  · 房间创建/加入/列表 │
│   · 断线快照(pendingJoin)  · 单点登录  · 踢人  · 健康监控    │
└──────────────────────────┬──────────────────────────────┘
┌──────────────────────────▼──────────────────────────────┐
│ src/game.js — GameRoom 状态机 (服务端权威)                │
│   · 玩家/座位/盲注/行动校验 · 街推进 · 摊牌 · 边池结算      │
│   · 断线托管 · AI 机器人 · 积分等级                        │
└──────────────────────────┬──────────────────────────────┘
┌──────────────────────────▼──────────────────────────────┐
│ src/poker.js — 牌型评估 + 起手牌胜率表                    │
│   · evaluateBest (2~7 选 5) · 长短牌两套规则 · 蒙特卡洛表   │
└─────────────────────────────────────────────────────────┘
src/accounts.js (游客 accountId) · src/auth.js (正式账号, scrypt 哈希)
```

- **服务端权威**：发牌、行动校验、结算全部在服务器完成，前端只渲染，天然防作弊。
- **无数据库**：账号/积分以 JSON 落盘（`data/accounts.json`、`data/users.json`），
  内存缓存 + 800ms 防抖写盘；重启即重置（仅账号数据持久）。
- **传输**：强制长轮询（`transports: ['polling']`），兼容 Cloudflare 隧道；心跳放宽适应手机后台。

## 二、对局状态机

```
 waiting ──房主开始/全员确认──▶ preflop ──▶ flop ──▶ turn ──▶ river ──▶ showdown
    ▲                                                                    │
    └─────────────── 结算确认(全员 ready) ◀─────── settle ◀───────────────┘
                                │ 不足 2 人/无真人 → resetToWaiting
```

| 状态 | 含义 | 进入条件 | 离开条件 |
|---|---|---|---|
| `waiting` | 等待开局 | 创建/清理 | `tryStart()` 有效玩家≥2 且全 ready、无人破产 |
| `preflop` | 翻牌前 | 发牌 + 盲注 | 一轮下注完成 |
| `flop/turn/river` | 三/四/五张公共牌 | 上一街完成 | 本街下注完成 |
| `showdown` | 摊牌（3s 展示期） | 只剩 1 人 / 全员全下 / 河牌后 | 2.8s 后分发 → 2.5s 后进 settle |
| `settle` | 结算确认 | 分发完成 | 全员 ready（自动开局）/ 人数不足（回 waiting） |

### 关键流程节点

1. **开局 `startHand`**：庄家轮转（座位升序取最小座位起，逐局 +1）→ 定 SB/BB
   （2 人局：庄家=SB；3+ 人局：庄家下家 SB、下下家 BB）→ 洗牌发 2 张 → 贴盲注 →
   preflop 首个行动者 = BB 下家（2 人局 = SB）。
2. **行动 `doAction`**：fold / check / call / raise / allin，服务端逐项校验：
   轮到谁、是否可过牌（toCall>0 拒绝）、加注是否 ≥ `currentBet + minRaise`
   （筹码不足时按全下处理）。
3. **街推进 `afterAction`**：每步先判断——只剩 1 人未弃牌 → 直接赢；
   无真人参与（全员托管）→ 发完公共牌摊牌；全员全下 → 发完公共牌摊牌；
   本轮全员行动且 bet 对齐 → `advanceStage`；否则 `advanceTurn` 找下一行动者。
4. **摊牌 `finishHand`**：评估 7 选 5 → 排序 → 边池分配 → 结算积分 →
   进入 `settle`（AI 输光自动借钱/欠款过多自动退出；人类输光须借钱或放弃才能确认）。
5. **边池 `distributePot`**：按 totalBet 层级切池（每层 `contrib × 参与人数`），
   从高池到低池、每池按最佳牌型分给未弃牌者，整除余数给第一位赢家。

### 行动顺序与座位

- `seatOrder()`：从庄家下家开始的座位循环（`[dealer+1, ..., dealer]`）。
- `nextToActSeat()` / `nextActiveSeatAfter()`：跳过已弃牌/已全下玩家。
- 离线玩家：45s 宽限期内跳过（给重连机会）；超过 45s 自动「免费过牌 / 需跟注则弃牌」。

## 三、断线 / 重连 / 托管机制

| 场景 | 行为 |
|---|---|
| 断线（轮到行动） | 标记 `suspended`，重启 45s 计时器；超时自动过牌/弃牌；重连 `clearSuspend` 恢复行动 |
| 断线（未轮到） | 45s 宽限期内跳过行动；超过自动托管（过牌/弃牌） |
| 主动离开（托管） | `markAway`：本局 AI 代打，座位保留置灰，下局不参与；回来恢复 |
| 断线 2 分钟未回 | server 移除玩家（`removePlayer`），底池投入记为 `orphanBets`；5 分钟内可凭快照 `restorePlayer` 恢复座位与筹码 |
| 单点登录 | 同一正式账号新登录顶掉旧连接（发 `duplicate_login` 后断开） |
| 被踢 | `kickedClients` 记 clientId，5 分钟冷却，禁止自动重连 |

## 四、发现的问题与修复（本轮）

### 🔴 修复 1：BB 短全下时 `currentBet` 未封顶（规则 bug）

- **位置**：`src/game.js` `startHand()`
- **问题**：盲注固定 `currentBet = bb`。若 BB 筹码不足（如 bb=10 只有 3 筹码，全下 3），
  currentBet 仍为 10，导致 SB 被迫「再跟 5」（SB 已下 5），其他玩家被迫跟完整大盲——
  而 BB 实际全下额只有 3，规则上有效下注应为 3。
- **修复**：`currentBet = Math.min(this.bb, bb.bet)`——以实际投入封顶；
  短盲全下产生的差额由边池机制自然处理。
- **验证**：`test/fixes.test.js` 用例 1。

### 🔴 修复 2：短全下加注后 `minRaise` 被错误缩小（规则 bug）

- **位置**：`src/game.js` `doAction` 的 `raise` / `allin` 分支
- **问题**：`minRaise = delta` 无条件更新。若玩家全下加注的增量不足当前最小加注
  （短全下），minRaise 被缩小为该短增量，后续玩家就能以低于门槛的增量再加注，
  破坏最小加注规则。
- **修复**：仅当 `delta >= this.minRaise`（完整加注）时才更新 `minRaise`。
- **验证**：`test/fixes.test.js` 用例 2。

### 🔴 修复 3：对局中移除玩家时筹码泄漏（`orphanBets` 记错金额）

- **位置**：`src/game.js` `removePlayer()` / `forfeit()`
- **问题**：`orphanBets += p.bet` 只记录**当前街**下注。若玩家在非行动轮被移除
  （如断线超时，当前街 bet 已被 `newBettingRound` 清零为 0），其前几街投入
  （含在 `totalBet` 中、已进入底池）既不在剩余玩家的层级计算里，又没记入残余注——
  这些筹码直接蒸发。
  > 例：3 人各投入 30，C 在 turn 被移除（bet=0, totalBet=30）→ 底池 90，
  > 层级只能重建出 60，C 的 30 消失。
- **修复**：`orphanBets += p.totalBet`（本局全部投入）；settle 阶段（已分发完毕）不再记。
- **验证**：`test/fixes.test.js` 用例 3（旧逻辑下 A+B 只剩 2000，修复后 2030 守恒）。

### 🔴 修复 4：`finishHand` 结算窗口内可二次分发（筹码翻倍隐患）

- **位置**：`src/game.js` `finishHand()`
- **问题**：防重入标记 `_settlePending` 在 2.8s（分发时刻）即重置为 false，
  而状态到 5.3s 才切到 `settle`。这 2.5s 窗口内若有路径重入 `finishHand`
  （如断线玩家 2 分钟移除计时器恰好触发 `removePlayer → afterAction → finishHand`），
  会**再次分发底池 → 筹码凭空翻倍**。
- **修复**：`_settlePending` 覆盖完整结算窗口（进入结算 → 进入 settle 全程为 true），
  窗口内一律拦截；同时给整个结算流程加异常兜底（任何异常也强制进入 settle，
  杜绝房间永久卡死在 `showdown` 导致「下一局无法自动开始」）。
- **验证**：`test/fixes.test.js` 用例 4。

### 🟡 修复 5：短牌起手牌分级错误（展示问题）

- **位置**：`src/poker.js` `handTier()`
- **问题**：短牌（6+）A6s 被分到 C 档（`low >= 7 + t`，t=1 → 要求 low≥8，A6/A7 落空），
  与代码注释「短牌 A6s+」矛盾；短牌 A6s 实际强度 ≈ 长牌 A9s，应为 A 档。
- **修复**：短牌放宽到 `low >= 6`（短牌最小牌面 6），长牌维持 `low >= 7`。
- **验证**：`test/fixes.test.js` 用例 5。

### 🟢 优化 1：起手牌胜率表磁盘缓存（启动阻塞 7-9s → 1ms）

- **位置**：`src/poker.js` + `server.js` 预热
- **问题**：启动时预热长/短两套 169 起手牌胜率表（各 600 次蒙特卡洛模拟），
  阻塞事件循环约 7~9s，期间服务器无法响应任何请求。
- **优化**：构建结果落盘 `data/winrate-long.json` / `winrate-short.json`
  （带版本 + 模拟次数校验，口径变化自动重建）；后续启动直接加载，实测 **1ms**。
- **验证**：`test/fixes.test.js` 用例 6；`server-3100.log` 显示 `[预热] 起手牌胜率表就绪 (1ms)`。

## 五、审查结论（未改动但值得知晓）

1. **胜率近似模型**：`getWinRateMulti` 用「vs 1 人胜率 × 衰减系数」近似多人胜率，
   非精确模拟（精确模拟成本过高），仅供 AI 与牌力面板展示。
2. **不烧牌**：发 flop/turn/river 前未执行标准烧牌（burn card），对公平性无实质影响。
3. **短全下「是否重新开放加注权」**：本实现中短全下仍允许后续玩家加注（宽松规则），
   若希望严格按 TDA「短全下不重开加注权」可再收紧。
4. **`distributePot` 的 `winners` 参数未使用**：函数内部按 totalBet 层级自行重建池，
   参数仅为历史遗留，无功能影响。
5. **断线宽限的「免费过牌」语义**：断线 45s 宽限期内轮到行动会被跳过，
   视为免费过牌（牌保留、不弃牌）——这是刻意的「给重连机会」设计。

## 八、加注逻辑审查（第二轮）

### 现状（`src/game.js` `doAction`）

| 校验 | 规则 |
|---|---|
| `raise` 目标 | `raiseTo` 为**目标总额**（含此前投入）；必须 `> currentBet` |
| 最小加注增量 | `raiseTo - currentBet >= minRaise`；筹码不足（全下）时豁免 |
| 筹码上限 | `real = min(raiseTo - bet, chips)`，不足则按全下处理 |
| minRaise 更新 | 仅**完整加注**（增量 ≥ 当前 minRaise）才更新门槛；短全下不降低后续门槛（上轮已修） |
| 短全下 | 不改变 currentBet 的差额部分按边池处理，不重开已行动玩家的加注权（宽松规则，未强制 TDA「短全下不重开加注」） |

### 客户端联动（`public/game.js`）

- 最小合法加注目标 = `currentBet + minRaise`（读服务端状态，`betMinRaiseTo`），滑块/按钮不足时自动吸附；pot-raise 按钮按标准「跟注额 + 底池×比例」计算。**与服务端校验完全一致，无需改动。**

### 结论

加注体系逻辑正确（含上轮修复的短全下门槛保护）。唯一可选项：若想严格遵循 TDA「短全下不重新开放已行动玩家加注权」，需在 `afterAction` 的 roundDone 判断中额外跟踪"本轮是否有完整加注"，当前实现允许已过牌玩家在短全下后再次加注（对朋友娱乐局影响可忽略）。

## 九、发牌与大小盲移动审查（第二轮）

| 环节 | 现状 | 结论 |
|---|---|---|
| 庄家轮转 | 首局取有玩家的最小座位；此后在**参与本局**的玩家（排除托管离开）座位中 `cur+1` 循环 | ✅ 正确（会跳过 away/断线玩家） |
| 盲注座位 | 3+ 人：庄家下家 SB、下下家 BB；2 人局：庄家兼 SB、对手 BB | ✅ 标准规则 |
| 发牌 | 洗牌 → 每人按座位升序轮发 2 张（先一圈再一圈） | ✅ 公平（每人 2 张随机牌）；仅起始座位按座位号而非庄家下家，无公平性影响 |
| 盲注金额 | SB=bb/2、BB=bb；筹码不足时全下，`currentBet` 以实际投入封顶（上轮已修） | ✅ |
| 盲注玩家破产 | 开局前校验 `chips > 0`，破产须 buyin 才能开局 | ✅ |
| 提前结束 | 一人未弃牌 → 立即赢池，公共牌留档展示 | ✅ |

**结论**：庄家轮转、SB/BB 移动、发牌逻辑均符合标准德州规则，无 bug。小改进点（未改，仅记录）：发牌可从庄家下家开始以贴合真实扑克习惯（当前按座位升序，公平性不受影响）。

## 十、结算窗口优化（完整展示、无需拖动）

### 问题

原结算面板（`#showdown-panel`，宽 520px、高上限 82vh）：
- 每行是**单行横向**排布（名次+昵称+底牌2张+最佳5张+牌型+标签），满桌 10 人时行高合计远超一屏 → 必须上下拖动；
- 桌面 520px 宽放不下 7 张牌 + 标签，行内容横向溢出被裁剪（行未设换行）。

### 优化（`public/game.js` + `public/style.css`）

1. **行结构改两行式**：上排 = 名次/昵称/牌型/赢家标签，下排 = 底牌 2 张 + 最佳 5 张（自己显示完整公共牌 5 张）；去掉冗余的"底牌/最佳5张"列标签。
2. **玩家 ≥4 自动两列网格**：`#sd-list.sd-grid`（`repeat(2, minmax(0,1fr))`），行高减半。
3. **卡片固定紧凑尺寸**：结算面板不再跟随桌面大牌尺寸（`--card-w`），改用 `clamp`（桌面）与固定小尺寸（手机 ≤640px：底牌 24×34、最佳 18×25），保证两列下 7 张牌一行放下。
4. **面板加宽加高**：`min(680px, 95vw)` / `max-height: 92vh`；公共牌区/横幅/行距全部收紧。
5. **≤380px 超窄屏**：卡片再缩一档 + 隐藏赢家标签。

`test/sd-layout-scan.js` 扫描 2/3/4/6/8/10 人 × 含/不含弃牌行 × 桌面/手机，断言 `scrollHeight <= clientHeight`（无滚动）：

## 十二、网络优化（减少"卡"体验）

### 实测基线（修改前）

| 项目 | 修改前 | 问题 |
|---|---|---|
| 传输 | **强制长轮询**（`transports:['polling']`） | 本地往返 36ms、隧道 ack 1020ms；隧道日志大量 `Incoming request ended abruptly: context canceled` |
| 每次广播负载 | `toState()` 14.2KB，其中 **gridTiers 占 9.8KB（69%）** | 10 人每行动一次广播 142KB，弱网下明显卡顿 |
| 静态/轮询响应 | 无压缩 | 80KB style.css / 94KB game.js 裸传 |

### 优化措施（均已实施并实测）

1. **放开 WebSocket**（`server.js` + `public/game.js`）：`transports: ['polling','websocket']`——
   轮询优先建立，随后自动升级 WS；**升级失败自动回落长轮询**，不影响隧道部署；
   可用环境变量 `TRANSPORTS=polling` 强制轮询。
   - 实测：本地 WS **6ms（ack 0ms）** vs 轮询 36ms；**隧道 WS 403ms vs 轮询 1020ms（快 2.5 倍）**，
     WebSocket 可正常穿透 trycloudflare。
2. **gridTiers 移出广播**（`src/game.js`）：13×13 起手牌热图是房间级静态数据，
   改为随 `hand:eval`（打开牌力面板时）按需下发，不再每次广播。
   - 实测：`room:state` 大小 **14.2KB → 1.4KB（-90%）**，10 人每行动广播 142KB → 14KB。
3. **gzip 压缩**（`server.js` + `compression` 依赖）：静态资源与 socket.io 轮询响应统一压缩。
   - 实测：style.css 80KB → **21.9KB**（-73%）。
4. 重连健壮性（已有）：回前台/网络恢复自动重连、5s 自检补连、心跳放宽 —— 保持。

### 验证

- `test/transport-test.js`：本地/隧道 × polling/websocket/polling→ws 三态全部连通
- `test/net-opt.test.js`：gzip 生效、gridTiers 已移除且按需返回、歌曲资源编码 URL 可播放

## 十三、背景音乐不播放修复

### 根因

1. **浏览器自动播放策略**：带声音的音频必须由用户手势解锁。原实现只在**首次** `pointerdown`
   时解锁一次——部分浏览器（尤其 iOS 旧版）不认 `pointerdown` 为有效手势；且歌曲列表是
   `fetch(/api/music)` **异步**拉取，歌曲 `play()` 发生在手势窗口之外，被静默拦截
   （原 `.catch(() => {})` 吞掉错误 → **无任何音乐**）。
2. **无回退**：歌曲模式 `play()` 被拒后不切回合成 BGM，直接静音。
3. **`<audio>` 未挂载 DOM**：个别浏览器对未挂载元素的播放不稳定。

### 修复（`public/audio-engine.js` + `public/game.js`）

1. **常驻多事件解锁**：`pointerdown` + `touchend` + `keydown` 均监听（capture, passive），
   每次手势都 `init()+resume()`（幂等廉价），覆盖 iOS 等"pointerdown 不解锁"的浏览器。
2. **播放被拒自动回退合成 BGM**：`songAudio.play()` 拒绝 → `fallbackToSynthBGM()` 切回
   合成风格（记住 `_lastSynthStyle`），保证**始终有背景音乐**，不再静音。
3. **解锁后自动补播**：`AudioContext.onstatechange` + `resume()` 在 ctx 恢复 running 时
   重试被拦截的歌曲（`_songRetryPending` 标记）。
4. **`<audio>` 挂载 DOM**（隐藏）：改善 Safari/旧内核播放稳定性；`preload='auto'` 提前缓冲。
5. **加载失败回退**：歌曲 404/格式不支持（error 事件）→ 回退合成 BGM。

### 验证

`test/audio-fallback-test.js`（无头 Chrome，模拟 `play()` 被拒 → 恢复）：
```
1) init 后风格 = piano          (play 被拒 → 自动回退合成) ✓
2) resume 重试后风格 = piano    (仍被拒 → 保持合成)       ✓
3) play 允许后风格 = song       (解锁 → 自动切回真实歌曲)  ✓
4) 手动 jazz→song 后 = song     (风格切换正常)            ✓
== 音频回退逻辑通过 ==
```

## 二十一、v1.3.1 排行榜清理（按账号排名）

### 问题

- 同一玩家可能同时有**游客账号**(accountId) 与**正式账号**(username) → 榜单出现两条；
- "我"的高亮按**昵称**比对（`name === myName`）→ 昵称可重复/可改名，误高亮、无法区分；
- 大量从未参与对局的**僵尸游客**（`0 胜 0 负、积分 1000`）占满 top50。

### 清理与改造

1. **按账号排名**：`rank:list` 每条返回稳定账号标识 `account`（正式=username / 游客=accountId）+ `kind`；
   前端"我"的高亮改为 `account === (username || accountId)`，与昵称/改名无关。
2. **账号升级合并**：注册时前端携带当前游客 `accountId`（`auth:register` → `auth.register(..., guestAccountId)`）；
   - 若游客玩过（有战绩或积分≠1000）→ **战绩继承**到正式账号（注册不丢分）；
   - **删除该游客记录**（`accounts.removeAccount`）→ 榜单不再重复；
   - 用户记录保存 `guestAccountId` 关联，供榜单去重（防御残留）。
3. **僵尸游客过滤**：`rank:list` 跳过 `0 胜 0 负 且 积分 1000` 的游客条目（正式账号不滤）。
4. **展示区分**：正式账号行显示 `昵称 @用户名` 小字（同名可区分）；游客只显示昵称。

### 验证

`test/rank.test.js` 9 项断言全过：注册继承战绩(score=1420/wins=4/losses=2) ✓、
游客记录删除 ✓、guestAccountId 关联 ✓、榜单条目带 account/kind ✓、
榜单无重复账号 ✓、僵尸游客不入榜 ✓。

> 注：历史存量数据（已注册用户无 guestAccountId）无法追溯关联，其旧游客记录仍可能在榜；
> 新注册用户自动完成合并清理。僵尸游客仅从榜单展示中过滤，未删除数据文件（安全起见）。

- **修复**：筹码不足跟注（`toCall > max`）时滑块/输入 min 取 `min(跟注额, 全下额)`，
  默认值=全下；输入框/±10 步进直接按全下处理；主按钮点击前 clamp 到全下额 → 触发 all-in；
  文案显示「全下 5」「筹码不足跟注，将全下」。
- 验证：`test-render.html?short=1`（slider 5/5、输入5保持、主按钮=全下）；服务端
  `test/fixes.test.js` 用例 9（allin/call 全下被接受、筹码归零、raise 低于 currentBet 被拒）。

### 3. 玩家块布局（长方体方案，根治压盖）

- **三区划分**：屏幕上下留白 → 上=功能条(header)、下=操作框(action-bar)、中=牌桌区；
  牌桌区内所有玩家块**整体**落在中区，永不越界 → 不压盖。
- **每个玩家 = 一个矩形块**：头像 + 名字/段位/筹码/下注徽章 + **手牌并入块内**（不再独立定位，
  从根上杜绝手牌越界）；底部排玩家手牌在块内顶部（朝桌心），左右列玩家块横排（手牌并排朝桌心）。
- **布局求解器 `solveSeatLayout`**（每次渲染/缩放时运行）：
  - 玩家按槽位分四组（顶部排/底部排/左列/右列），块贴 racetrack 内壁排开，四角错开（各让一个块位）；
  - 约束① 块整体在 [功能条底, 操作框顶] 内；② 相邻块不重叠；③ 不压中央公共牌区；
  - 不满足 → 整体缩小牌桌（元素按 `--card-w/--avatar` 链等比缩小），仍不满足 → 自动调小
    牌/头像下限（`--card-min/--avatar-min`，最小 20/24px）→ **把牌头像变小塞进去**；
  - 6 人局列平衡：左列 2 块分 1 块到右列（每列 1 块，仅布局不影响行动顺序）；
  - 块高估算用实测校准 `_blockK`（渲染后量实际块高/估算比，下一帧收敛）。
- 结果：**桌面 1440×900 桌 1036×518、手机竖屏 390×844 桌 322×403**，四组（我回合/非我回合）
  全部无重叠、无 header 压盖、无操作条遮挡、无公共牌压盖。

## 二十五、v1.4.8 优化（横屏压盖 / 浏览器条让位 / 座位环避让）

### 1. 展开态操作条预留（根因修复）

- **问题**：`--actionbar-h` 在操作条折叠时测得（~60px），而轮到玩家行动展开后高达
  ~220px → 展开的加注条（fixed 底部）盖住桌子底部 117px（桌面）/ 44px（手机竖屏），
  底部头像/手牌被遮。
- **修复**：`updateViewportVars` 改测**展开态**操作条真实高度
  （`measureExpandedBarHeight`：临时加 `my-turn`、临时去掉操作条内所有 `.hidden`
  子元素、填入代表性文字（空内容时操作条更矮）再量，测完还原）；
  因操作条 `max-width` 依赖 `--table-w`（鸡生蛋），**两遍测量收敛**（先按旧桌宽测高
  → 定桌宽 → 再测高 → 重定桌宽）。
- 删除 render() 里残留的"用当前折叠高度覆盖 `--actionbar-h`"旧代码。

### 2. 桌面/横屏桌子尺寸按展开操作条让位

- `--table-w = min(96vw, (vh - 头部 - 展开操作条 - 上内边距 - 20) × 2)`：
  桌高 = 可见区高 - 头部 - 展开操作条 - 安全间隙，桌子不再钻到操作条下面。

### 3. 竖屏桌子尺寸改为 JS 驱动

- 原 CSS 竖屏 `max-height: 62vh` 不含展开操作条高度 → 桌子溢出到操作条下。
- 改为 JS 按可见区真实高度计算 `--table-w`（高 = vh - 头部 - 展开操作条 - 间距，
  宽 = 高×0.8，aspect 4/5，上限 86vw）；CSS 竖屏 `#table` 直接使用 `--table-w`，
  移除固定 `max-height`。

### 4. 座位环避让（头像×手牌不再互相压盖）

- 底部排：头像 `botY 98`（贴桌底边）/ 手牌 `botY 78`（上移错开）；
- 顶部排：头像 `topY 7`（下移避开 room-header）/ 手牌 `topY 21`；
- 竖屏侧排：头像 `pLeftX 3 / pRightX 97`（外扩）、手牌 `pLeftX 22 / pRightX 78`；
- 竖屏手牌环半径 `portR 36→40`（底部两副手牌不再 2.6px 重叠）；
- 新增**横屏矮屏**（手机横屏，高 < 500）专用参数 `RING_POS_LAND`
  （头像更靠顶/底、手牌更靠内）+ 横屏牌/头像再缩小（card 24px、avatar 26px 起）；
- 竖屏 `#app`/`#room` 高度改用 `var(--vh)`（visualViewport），横屏头部紧凑化。
